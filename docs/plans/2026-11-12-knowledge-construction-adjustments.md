## B 原逻辑如何调整
| 问题 | 当前做法 |
|---|---|
| 旧结果套用新文件时间戳 | 同一批输入字节生成内容摘要 |
| 缓存只认模型名称 | 内容、协议、端点与处理版本共同绑定 |
| 追加漏来源、替换留旧来源 | 追加取并集，完整替换取当前集合 |
| 只读局部却覆盖整模块 | 聚合全部有效观察，缺项不替换 |
| 返回越界、重复或缺失路径 | 严格校验，保留有效项并记录缺项 |
| 空内容被迫重试 | 文件、模块、单条知识均可 skip |
| 逻辑结果代替实际请求数 | 每次请求含重试，先预留预算再发送 |
| 领域目录被当成文件证据 | 目录是范围，实际文件是来源 |

## C 现在怎样生成与写入 {span=2}
```flow
读取版本 -> 文件观察: 同字节哈希与摘录
文件观察 -> 完整模块: 复用未变化的观察
完整模块 -> 校验候选: 脱敏与响应校验
校验候选 -> 不写入: 来源或依据变化
校验候选 -> 正常跳过: 没有新判断
校验候选 -> AI 草稿: 全新或未被人工修改
校验候选 -> 更新建议: 原文有人工内容
更新建议 -> 人工接受: 对照基线与来源
人工接受 -> 当前版本: 归档原文
```
首次确认未编辑的生成稿仍检查来源版本。
人工已确认的知识可以在复核后重新确认。

## D 什么保护仍然保留
- AI 不直接覆盖人工编辑或确认过的原文。
- 接受更新前检查原文版本及生成来源。
- 当前版本之外的原文留在 revisions。
- 草稿、过期或无法核验的知识不充当 AI 依据。
- 相关域的人工约定可召回，但不是实现证明。
- 整体进度表示处理覆盖，不是知识正确率。
- 保存失败显式中止，不伪报完成。

未变化文件仍在本地读取以校验摘要。
请求数记录发送前的持久化预留。
它不是服务商账单，取消竞态可能保守计数。
