# Qiyide：把“点了不知道发生什么”改为可理解、可控制、可恢复的交互

## 结论

这次不是只缺一根进度条。架构生成首先有一个**视图状态判断错误**：没有知识条目和领域模型时，窗口用“还没有知识条目”替换整个内容区。架构页签、生成按钮和唯一的构建中指示都会消失。即使已经生成架构，该条件也没有检查架构数据，仍可能隐藏结果。

建议先修这个状态边界，再统一任务反馈。不要给每个按钮各补一个转圈，也不要把所有长任务都改成阻塞弹窗。

## 2. 用例详述

### 2.1 UC-38：首次生成系统架构

**参与者**：查看项目结构的研发。

**前置条件**：已打开本地项目，可以读取项目文件。**不要求**已有知识条目、领域模型或锁定模型。

**后置条件**：用户看到清晰的终态；成功时可以读取完整架构产物；失败/取消时旧产物和知识保持原状。

**主成功场景**：

1. 用户进入“系统架构”。页签、视角标题和操作区始终保留。
2. 空态显示“尚未生成系统架构”，提供“生成架构视图”。
3. 用户点击。按钮原位改为“生成中…”，常驻任务条立即出现。
4. 系统显示“检查项目与执行方式”。对输入范围、模型能力、冲突任务先做判断。
5. 系统在后台扫描。先显示已发现文件数；分母未知时不显示百分比。
6. 系统分析依赖。显示真实的模块/解析数和当前阶段。
7. 复杂分组使用 AI 增强；显示“等待模型返回结构化结果”、耗时、实际模型与尝试次数。
8. 系统校验结构和输入版本。重复归属、未知模块、缺失模块按明确规则处理并记录警告。
9. 系统提交产物、读取验证，再发布完成状态。
10. 仍在架构视角时更新画布；已切到其他视角时不抢焦点，给“查看结果”。
11. 结果标明执行来源、生成时间、输入版本与“AI 草稿/静态分析”，不标成业务已验证。

**替代流程**：

- A1. 模型未配置：AI 增强不可执行；显示“去配置 AI”和“仅静态分析”。不能把本地扫描能力一起禁用。
- A2. 候选组足够简单：跳过模型阶段，标明“静态分析生成”。不要显示模型正在工作。
- A3. 没有受支持代码：显示扫描范围与排除数量，提供调整范围/查看支持类型。不要提示“先新建知识”。
- A4. 相同项目已有同类任务：转到既有任务详情，不再启动一份。
- A5. 有旧架构：重建时保留旧图和版本标识；新产物可靠保存后再切换。
- A6. 用户离开视角或关闭知识库窗口：任务按产品明确的后台规则继续；重开可订阅同一任务。
- A7. 用户关闭项目：若资源可继续访问，明确提供后台继续；权限/项目上下文将失效时取消并保留旧产物。不能默默改变任务归属。

**异常场景**：

- E1. 扫描失败：说明目录/权限原因，显示失败阶段，不把它当空仓。
- E2. 模型响应慢：保持等待状态；显示已用时间和取消。不用停在 90% 伪装进度。
- E3. 请求超时/限流：显示尝试次数、可恢复原因；自动重试也必须可见且受预算限制。
- E4. 模型返回空内容/无效 JSON：保留扫描结果；重试模型阶段，必要时提供明确标注的静态结果。
- E5. 写盘失败：显示“生成完成，但未保存”；保留候选、旧架构和保存重试入口。**不能显示任务成功**。
- E6. 生成期间项目内容或模型配置变化：不得让旧回调覆盖新任务；保留候选并说明需要基于新版本重新生成。
- E7. 正常取消：显示“已取消，未替换原架构”。取消不是“架构划分失败”。

**业务规则**：BR-01、BR-02、BR-03、BR-04、BR-05、BR-06、BR-09。

### 2.2 UC-39：整仓建档、暂停与继续

**前置条件**：本项目可读，AI 配置有效；任务范围和预算已确认。

**后置条件**：已完成部分可读取；剩余、失败、跳过与预算停止分别有记录。

**主成功场景**：

1. 打开建档面板，先显示“正在统计范围”，后台统计候选文件。
2. 展示整仓范围、预算上限、已处理、待处理和调用策略。
3. 开始后显示三个不同信息：整仓覆盖、当前轮次、当前阶段批次。
4. 每批完成更新真实计数；模型在飞时显示等待与耗时。
5. 所有写入可靠结束后，根据剩余项发布“全部完成”或“部分完成”。

**替代流程**：

- 暂停：发布“等待安全点暂停”。保留已完成批次与检查点；明确当前批次/轮会继续多久，提供真正取消入口。
- 继续：从有效检查点重建待处理队列，不把缓存存在等同于知识仍存在。
- 预算触顶：显示“达到调用/时长上限，仍有 X 项待处理”，不是完成 100%。
- 打开其他项目：显示该项目自己的任务。已有单例暂不能并行时，明确提示忙的是哪个项目，并提供“查看该任务”，不能静默拒绝。

**异常场景**：停止进入 `cancelling`，等待底层工作退出后才可启动新的冲突任务。已取消任务的迟到回调不再更新任何当前任务状态或产物。

### 2.3 UC-29：视角切换与上下文详情

**前置条件**：项目已打开；每类资源可以独立为空。

**主成功场景**：

1. 页签为“知识条目 / 领域模型 / 代码结构 / 知识关系 / 系统架构”。
2. 切换只改变当前内容和局部操作，不移除导航，不改变正在运行任务。
3. 每种视角使用自己的选择对象与详情类型。
4. 系统架构选中某个域时，右栏显示职责、模块、依赖、来源版本，而不是旧知识条目的详情。
5. 全局任务条只显示与当前项目相关的任务；不同项目的活动在活动中心明确分组。

| 视角 | 数据依赖 | 正确空态 | 首要动作 |
|---|---|---|---|
| 知识条目 | 知识 entries | 尚未记录知识 | 新建规则 / 从改动提炼 |
| 领域模型 | MindGraph | 尚未识别领域 | 识别领域 |
| 代码结构 | 可扫描的仓库文件 | 正在读取结构 / 未发现受支持代码 | 重新扫描 / 调整范围 |
| 知识关系 | 知识节点与关系 | 尚无知识关系 | 创建知识 / 查看条目 |
| 系统架构 | architecture 产物或可扫描代码 | 尚未生成系统架构 | 生成架构视图 |

**设计规则**：查询、类型、草稿、领域筛选属于知识视角。系统架构的过滤应是域、层、模块；不能让“只看草稿”影响看起来无关的图。

### 2.4 UC-15：暂停后恢复任务

**前置条件**：选中仍存在的运行进程。

**主成功场景**：点击暂停 → 请求 SIGSTOP → 确认停止 → 显示“恢复” → 请求 SIGCONT → 确认运行 → 显示“暂停”。

**异常场景**：进程已退出/信号失败时显示真实原因，不更新成 running。当前 `resume()` 要求 `status == .running`，与恢复按钮可用条件 `status == .stopped` 矛盾，需要直接修正并测试。

### 2.5 UC-27 / UC-28：知识确认与批量变更

- 保留原文对照、内容摘要、来源版本与人工核对记录。
- 单条编辑保存失败不关闭编辑器，不丢正文。
- 更新建议不能绕过原知识版本检查，也不能在快捷菜单里直接当新知识确认。
- 批量确认前列出实际可确认对象；完成后显示成功/跳过/失败及原因。
- 删除进入废纸篓；不可恢复的副作用才使用明确确认。
- 接受知识更新、采纳结构判断与业务验收是不同动作。界面不能把它们共用成“已验证”。

## 3. 统一交互规则

### 3.1 状态至少分成三层

**资源状态**：未加载 / 首载中 / 刷新中 / 可用 / 无数据 / 无匹配 / 读取失败。

**任务状态**：待开始 / 前置检查 / 运行中（阶段、计数、尝试）/ 正在取消 / 已取消 / 全部完成 / 部分完成 / 失败。

**可信度属性**：静态推断 / AI 草稿 / 人工核对 / 来源已变化 / 有执行验证证据。`stale` 是产物属性，不是普通任务失败。

不要再用一个 `isEmpty` 决定整个窗口，也不要用一个 `Bool` 表达所有任务状态。

### 3.2 反馈位置：推荐“常驻任务条 + 原位按钮 + 活动详情”

1. **原位按钮**：保留动作名称，运行时变为“生成中…”。不要用无文字的小转圈替换整个入口。
2. **常驻任务条**：放在项目/视角导航之后、内容之前。显示动作、阶段、真实计数或等待状态、耗时、取消/查看详情。
3. **活动详情**：复用 ActivityViewer/通知入口，显示阶段记录、警告、重试、失败原因、产物位置。
4. **结果定位**：完成时本视角可更新内容；其他视角只出现“查看结果”，不强制跳走。

**替代设计**：“任务抽屉”。适合同时查看多个长任务；主画布保留，右侧显示任务详情。优点是细节完整，代价是占用宽度。第一版以常驻任务条为默认，抽屉作为“查看详情”的展开形态。

**不推荐**：所有生成都开阻塞弹窗。它只能解决显眼程度，不能解决后台、切换、多项目和取消真实性。

### 3.3 不虚构进度

- 扫描分母未知：`已发现 1,284 个文件` + 不确定进度；该数字在原型中仅为示例。
- 依赖解析分母已知：`已解析 84 / 120 个模块` + 可量化进度。
- 模型返回时长未知：`等待模型返回结构化结果 · 已用 38 秒 · 第 1/2 次尝试` + 不确定进度。
- 阶段可显示 `3 / 5`，但不把它换算成“整个任务 60%”。
- 整仓显示真实覆盖比例，同时单独显示轮内批次比例。分母按输入快照定义；项目变化则开启新版本统计。
- 自动重试、静态降级、跳过 AI 和部分失败必须可见。

现有 HTTP 资源超时设置为单次 300 秒，架构预算配置可尝试两次。工具提示“约一分钟”不是可靠的执行时间保证。没有历史统计时不报预计完成时间。

### 3.4 取消、暂停、关闭不能混用

| 动作 | 含义 | 界面要求 |
|---|---|---|
| 取消任务 | 不再计算/发送请求/提交新产物 | 先“正在取消”，资源退出后“已取消” |
| 暂停 | 在可恢复安全点保存检查点 | 显示等待安全点；明确已完成/未完成范围 |
| 收起面板 | 隐藏细节，任务继续 | 常驻活动入口仍可见 |
| 关闭窗口 | 关闭视图订阅 | 根据明确任务策略继续或取消，不能偷偷改变 |
| 关闭项目 | 项目上下文可能失效 | 说明后台权限/产物位置，必要时取消并保存已完成部分 |
| 保存提交阶段 | 短暂不可中断的原子提交 | 文案说明“正在保存，暂不可取消”，不是莫名禁用 |

### 3.5 错误与无结果要给下一步

| 情况 | 文案方向 | 主动作 |
|---|---|---|
| AI 未配置 | AI 增强未配置；本地分析仍可用 | 去设置 / 仅静态分析 |
| 无匹配 | 当前筛选未找到结果 | 清除筛选 |
| 无可处理变化 | 工作区干净 / 0 项待处理 | 换输入范围 |
| 等待较久 | 暂未收到模型结果；仍在等待 | 查看连接信息 / 取消 |
| 响应无效 | 模型没有返回有效结构 | 重试模型阶段 / 静态替代 |
| 写盘失败 | 结果未保存；旧版本未替换 | 重试保存 / 导出候选 |
| 来源变化 | 输入版本已变化；未覆盖原结果 | 基于新版本重建 |
| 正常取消 | 已取消；已完成部分保留 | 继续 / 重新开始 |
| 部分失败 | 完成 X 项，失败 Y 项 | 查看失败项 / 仅重试失败项 |

错误按操作 ID 关联。关闭某个横幅只关闭该横幅，不清除另一个任务的错误。架构错误的关闭按钮应清除 `architectureError`，而不是只清除 curator 字段。

### 3.6 短操作与表单

- 复制：按钮原位短暂显示“已复制”，不要打开通知弹窗。
- 保存：可靠写入后显示已保存；错误时保留正文、字段和光标。
- 导出：取消保存面板是正常退出；成功显示文件位置，提供打开/定位。
- 新建/改名：重名与格式错误就地提示；焦点留在需要修正的字段。
- 删除/覆盖/强推：显示对象数量、目标与后果；安全可逆操作提供撤销。
- 批量任务：不要只显示“成功”；分别统计成功、跳过、失败并保留失败队列。
- 未实现入口：隐藏或禁用；不可用但可解决的入口提供原因和设置入口。不要保留可点击的空动作。

### 3.7 无障碍与视觉规范

- 使用原生 `ProgressView` 与系统语义颜色；长任务指示不再缩小成难以发现的图点。
- 主正文设计基准 13pt，辅助信息 11–12pt；关键状态不能只放在 9pt 小字或 hover 提示中。
- 状态使用文字 + 图标，不能只靠红/绿。
- `accessibilityLabel` 包含动作与阶段；计数按节流策略更新；耗时每秒更新，不逐字打断 VoiceOver。
- 支持键盘导航、Escape 收起可关闭面板、明确焦点恢复；取消任务与关闭窗口使用不同命令。
- 在 900 / 1280 / 1680 宽度、深色、高对比度与减少动态效果下验证。对架构优先让出画布宽度，不强制保留两个空知识栏。
- 页面标题统一为“项目 · 知识与架构”。“导图/结构/图谱/架构”改为表达对象的完整名称；迁移时保留熟悉入口与快捷键。

## 4. 业务规则与技术落点

### 4.1 规则

- **BR-01 视角独立**：资源 A 的空态不能遮住资源 B 的页面或任务。
- **BR-02 输入快照**：任务绑定项目、输入范围、模型配置与输入版本。
- **BR-03 一次启动**：同项目同作用域的冲突写任务去重或排队，不能静默重复执行。
- **BR-04 可靠完成**：校验、写入、读取验证与版本检查通过后才能显示产物成功。
- **BR-05 正常取消**：取消必须作用到底层工作；取消不是失败。
- **BR-06 无迟到覆盖**：旧任务、旧视图、旧模型配置和旧输入的回调不能提交当前结果。
- **BR-07 输入保护**：失败与刷新不得丢失用户正在编辑的内容。
- **BR-08 有效统计**：分母未知时不显示完成百分比；部分完成不显示全部成功。
- **BR-09 可信度分层**：任务完成、AI 草稿、人工核对、业务验证分别展示。
- **BR-10 安全副作用**：有外部副作用的取消需要对账；不可逆操作明确确认。
- **BR-11 上下文明确**：每个操作说明项目、对象、范围、目标和不可执行原因。
- **BR-12 不泄露凭据**：模型、日志、导出、任务详情不展示密钥或未脱敏敏感文本。

### 4.2 项目级操作注册表，而不是重写所有执行器

建议新增一个显示与生命周期适配层。保留现有 TaskManager、AIReviewService、WikiCurationRunner、领域分析器和知识来源校验；逐个接入共同契约。

```swift
// 设计草图，尚未实现。
struct OperationSnapshot {
    var id: UUID
    var projectID: ProjectID
    var kind: OperationKind
    var inputRevision: InputRevision
    var phase: OperationPhase
    var progress: MeasuredProgress?  // 未知分母则为 nil
    var elapsed: Duration
    var attempt: AttemptInfo?
    var capabilities: OperationCapabilities
    var warnings: [OperationWarning]
    var outcome: OperationOutcome?
}
```

- `ProjectID` 使用明确的本地项目身份，不能只看窗口标题或仓库名。
- `InputRevision` 至少包含 HEAD、相关工作区内容摘要和模型配置版本；HEAD 相同不代表未提交文件没变。
- 注册表持有 Task 句柄与当前快照；视图只订阅。视图关闭不应成为丢失任务反馈的原因。
- 执行器输出阶段、真实计数、尝试、警告、候选、保存结果等事件。
- UI 按 `operationID + projectID + inputRevision` 校验更新。
- CPU 扫描/建图/预览在后台；UI 不在 body/onAppear 中同步遍历大仓库。
- `Task.cancel()` 是协作式取消。显式处理 detached 工作和 HTTP/原生进程句柄，不能只改 `isRunning = false`。

### 4.3 改动顺序

| 阶段 | 范围 | 完成条件 |
|---|---|---|
| M1 首建可用 | 独立空态、架构进度事件、前置判断、真实保存、可取消、可见结果 | 空知识库首次生成不失联；写盘失败不假成功 |
| M2 任务统一 | 注册表、活动适配、跨视角/窗口、错误关闭、暂停恢复修正、建档语义 | 同项目不重复；关闭重开能找到任务；取消后不接收迟到结果 |

先修行为与状态，不先做纯视觉换肤；不迁移已有效的知识可信度逻辑。

## 5. 验收规格

以下是拟定的验收条件，不是已经测出的结果。测试使用临时项目、假模型、假进程与可注入的文件写入器，不向真实服务发送代码。

| 场景 | 验收条件 |
|---|---|
| 空知识、空模型、空架构 | 五种页签和架构启动入口均可达 |
| 空知识、空模型、已有架构 | 已有架构仍显示，不落入知识空态 |
| 没有知识但有可扫描代码 | 代码结构与架构不要求先创建知识 |
| 首次点击 | 下一个可用 UI 更新周期显示准备状态；目标点击确认延迟小于 100ms，需实测 |
| 快速重复点击 | 同项目同范围最多一个执行任务，后续点击定位现有任务 |
| 启动阶段切视角 | 任务条仍可见；不取消；不抢回视角 |
| 关闭重开知识库窗口 | 恢复该项目原任务快照与进度，不启动第二份 |
| 两个项目同名 | 状态、产物和取消都不能串项目 |
| 模型未配置 | AI 增强给原因和设置入口；静态模式仍可使用 |
| 静态直出 | 模型阶段明确标为跳过；来源不冒充 AI |
| 模型慢响应 | 显示等待、耗时、尝试与取消；不伪造固定百分比 |
| 自动重试 | 显示真实尝试数；不越过预算；用户可取消 |
| 取消 CPU 扫描/HTTP | 先进入 cancelling；底层退出后才 cancelled；旧产物不替换 |
| 原子提交中取消 | 明确短暂不可取消；保存结果按真实返回发布 |
| 模型返回无效结构 | 失败阶段可恢复；缓存扫描可复用；静态替代明确标注 |
| 写盘/读取验证失败 | 不报成功；旧产物与编辑输入保留；可重试保存 |
| 输入在生成期间变化 | 原任务不覆盖新版本；候选结果明确失效 |
| 旧任务迟到回调 | taskID / revision 检查拒绝提交和 UI 更新 |
| 建档单轮结束但还有剩余 | 不显示整仓全部完成；轮内和整仓进度不混淆 |
| 预算触顶/部分失败 | 显示剩余与失败队列，不显示全部成功 |
| 暂停后恢复进程 | 假进程确认 `running → stopped → running`；失败保留 stopped |
| 关闭架构错误横幅 | 只关闭架构错误，不清掉其他任务状态 |
| 搜索无匹配 | 保留页签与筛选上下文，提供清除筛选 |
| 批量部分失败 | 摘要与失败对象准确；重试只处理失败项 |
| Git 收起/取消 | 收起不等于取消；已发生远端副作用先对账 |
| 深色/高对比/键盘/VoiceOver | 主操作可达；状态有文字；焦点、读屏与减少动态效果正确 |

## 7. 设计依据与交付边界
