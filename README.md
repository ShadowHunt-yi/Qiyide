## 简介

Qiyide 在 CodeEdit 的基础上做产品化与工程化改造：可以与原版 CodeEdit **并存安装**、界面**完整中文化**、
补上日常开发缺失的 Git 与多仓库能力、修复若干崩溃与卡顿，并提供可复现的构建与打包流水线。

以下功能均为**本仓库新增或重做**，上游 CodeEdit 不具备。

## 本仓库独有的功能

### 编辑器

| 功能 | 说明 | 入口 |
| --- | --- | --- |
| 行级 Git blame 标注 | 行尾显示提交哈希 / 作者 / 日期 / 摘要；按分支与文本指纹去重，编辑后合并刷新；标注按类型整体卸载，不会叠加 | 默认开启，⌥⌘B 切换 |
| 单行变更历史 | 查看某一行从引入到现在的全部提交与逐次 diff | ⌥⌘L |
| Markdown 源码 / 预览分栏 | 双栏实时预览、滚动位置双向同步；mermaid 图表离线渲染；渲染在后台线程并 350ms 防抖 | ⌥⌘P（仅 .md 生效） |
| 差异以编辑器标签打开 | 不再弹独立窗口：单击打开临时差异标签、双击固定、可拖到编辑区打开完整文件 | 源代码管理面板 |
| XML 族词法高亮 | 精确区分标签名、属性名、属性值、注释、CDATA、处理指令；只失效受影响行 | 自动（`.xml` / `.plist` 等） |
| 折叠带 | 代码折叠模型接入行号栏折叠带，折叠区间计算合并连续输入 | 行号栏 |
| 括号配对高亮修复 | 修复光标远离可视区域时 `NSRange` 越界导致的必崩问题 | 自动 |

### 多仓库工作区

| 功能 | 说明 |
| --- | --- |
| 仓库切换与聚合 | 顶部仓库切换器；「全部仓库」视图按仓库分组汇总改动，可一键跳转到对应仓库 |
| 新建终端选择仓库 | 多根工作区下工具栏 `+` 变成仓库下拉，选中即在该仓库根目录启动终端 |
| LSP 按仓库解析 | 语言服务器会话以「文件所属根目录」为键，次要根项目不再套用主根配置；关闭窗口时释放所有根的服务器进程 |
| 历史面板跟随文件 | 检查器「历史」显示当前文件所属仓库的提交，而不是当前活动仓库 |
| 逐仓库刷新 | 文件事件按根目录路由，每个仓库独立刷新分支、远程、改动与储藏 |
| 相对路径带根名 | 多根下复制相对路径会带 `<根目录名>/` 前缀，避免跨根歧义 |

### 性能与诊断

| 功能 | 说明 |
| --- | --- |
| 内置性能采样 | 记录启动、git 状态、blame、diff、文件树重载/展开、Markdown 渲染耗时；原始样本保留 1 小时并聚合为小时桶（30 天），文件硬上限 2 MB；另有主线程看门狗记录 >250ms 的停顿 |
| 性能摘要 | 「视图 → 复制性能摘要」输出各类别的次数、平均、p95、最大值，可直接用于定位优化方向 |
| 文件树提速 | 展示子项按数据代缓存、排序键预取（2000+ 项目录实测 478ms → 43ms）、紧凑目录链带环检测 |
| 索引瘦身 | 搜索索引跳过 `target/`、`node_modules` 等构建产物（实测索引量减少约 62.9%），正则预编译 |
| Git 刷新合并 | 文件系统事件 300ms 合并为一次 `git status`；改动列表渲染不建树；自动 fetch 由 10s 放宽到 180s |
| 缩略图保护 | 迷你地图只排版可视区域，内容高度超约 5000 行时停用，避免秒级主线程卡顿 |

### 稳定性修复

- 括号配对高亮的 `NSRangeException` 崩溃（SwiftUI 布局期间触发）；
- blame 错误分类：未跟踪 / 无提交 / 文件已删除 / 非 UTF-8 一律静默降级，只有真实故障才提示，且文案可读；
- 移除「全部展开」入口：大树下全量展开是 O(n²) 的主线程长任务；
- 历史时间显示为「现在」：修正 Git 日期解析（`%aD` + 本地化解析失败后回退当前时间）；
- 重命名 / 格式化进入撤销栈，并限制写入工作区范围内；
- blame 标注末行锚点：文件末尾无换行时不再吞掉最后一个可见字符。

### AI 改动审查

| 功能 | 说明 | 入口 |
| --- | --- | --- |
| 分层审查 | 每次提交按**业务架构 / 技术架构**归组（路径 + 模块映射规则），可分别查看两侧改动 | ⌥⌘R |
| 重要度分级 | 6 类确定性信号（回归修复、静默失败、公共 API、边界算术、并发/持久化、无测试、影响面）加权评分；高分展开、低分折叠为一行摘要 | 同上 |
| 声明级变化 | 从补丁中提取函数/类型/属性的增删，函数体内部改动单独标注，不必逐行读 diff | 同上 |
| 影响面 | 业务/技术文件数、声明变化数、增删行数一次给出 | 同上 |
| 清单导出 | 每提交生成 `.qiyide/changes/<hash>.json`（schema `qiyide.ai-review/1`），字段含层级、评分、信号、文件与符号，可被脚本消费 | 「导出清单」 |
| 审阅状态 | 已读标记本地持久化，按仓库隔离 | 详情页右上 |
| AI 叙述 | 为每次提交生成 2~4 句中文说明；支持 **OpenAI 兼容 / Anthropic 直连**，或**接入 cc-switch 本地代理**（密钥由 cc-switch 注入，切 Provider 自动跟随）；按提交缓存，失败静默降级到规则摘要 | 详情页「AI 叙述」 |

分层与评分**全部由确定性规则计算**，不依赖任何模型调用；模型只用于补充自然语言说明，清单中 `generator` 字段可区分来源（`deterministic-analyzer` 或 `deterministic-analyzer+<provider>:<model>`）。AI 叙述默认关闭，在「设置 → AI」中开启。

### 知识库（Wiki + 图谱）

| 功能 | 说明 | 入口 |
| --- | --- | --- |
| 知识条目 | 一个 Markdown 文件 = 一条知识，存在仓库的 `.qiyide/wiki/` 下，随代码一起提交与 review；六种类型（主题/决策/模块/规范/术语/事故） | ⌥⌘K |
| **AI 维护** | 知识由模型从改动中沉淀：审查窗口点「沉淀为知识」、知识库点「AI 整理」（读未提交改动）。产出一律是**草稿**，人在图谱上确认后才成为可信知识 | ⌥⌘R / ⌥⌘K |
| 草稿形态 | 草稿条目在列表标「草稿」、在图谱上带橙色虚线环；详情页顶部有「AI 起草 · 待确认」横幅与确认/丢弃 | 同上 |
| 关联 | 前置声明 `relations: 属于:某条目; 导致:另一条` 建立强关系；正文 `[[标题]]` 建立提及关系，自动维护反向链接 | 同上 |
| 图谱 | 力导向布局（确定性，同一份数据每次位置一致）；节点大小=关联数、颜色=类型、实线=声明关系、虚线=正文提及；选中高亮邻居、其余降透明度 | 同上 |
| 交互 | 点击节点看详情、拖拽微调、空白拖拽平移、双指缩放、按类型筛选、全文检索（标题 > 标签 > 正文） | 同上 |
| 审查联动 | 条目的 `sources` 与改动文件路径匹配；审查窗口详情页顶部直接列出「相关知识」 | ⌥⌘R → 详情页 |

**内置技能：仓库建档**

不是一次性提示词，而是一条固定流水线，每一步都可解释、可复现：

| 步骤 | 做什么 | 是否用模型 |
| --- | --- | --- |
| 1. 划分知识单元 | 自顶向下按「规模 + 命名同源 + 子目录收敛」算内聚度，够内聚的目录整块成单元，不够就下钻，最小到单文件 | 否 |
| 2. 建依赖图 | import 语句 + 符号引用（类型声明与引用倒排）两路抽边，得到单元级依赖、被依赖次数与拓扑序 | 否 |
| 3. 分辨重要性 | 按规模、入口文件、近期变更次数、是否测试/生成代码打分排序；跳过依赖与构建目录 | 否 |
| 4. 理解文件 | 按字符预算装箱（10 文件 / 24K 字符一批），并发 3 路阅读，产出职责与要点；已读过的直接复用 | 是 |
| 5. 梳理联系 | 依赖关系由图直接给出，模型只解释「为什么这样分层、有什么约定」，不再猜关系 | 是 |
| 6. 落成知识 | 每个单元一条 `status: draft` 条目；重跑整块替换（保留人写的「补充」），不会累积重复段落 | 是 |

**知识单元的粒度不是预设的。** 一个 500 行的核心协调器可以单独成条（单文件），
`Store + Graph + Entry` 这种可以合成一条（文件组），整个 `Features/Wiki` 也可以是一条（目录）。
实测本仓库 739 个源码文件切成 159 个单元，三种粒度并存，每个单元的切分理由（内聚度）写在条目里。

**先建图，再分析。** 依赖图是本仓库自己算出来的事实：837 条单元间依赖边，
被引用最多的是 `Settings/Models`（162 处）、`SourceControl/Accounts/GitHub`（118 处）。
模型看到的是「A 被 B 引用了 12 次」，而不是一串模块名——后者只能靠猜。
建档按拓扑序推进，基础模块先建，上层模块才能引用到真实存在的条目。

**整仓长任务**：默认「连跑至完成」，每轮 240 个文件、并发 3 路，触发调用上限或时长上限才收尾。
任务挂在应用级单例上，**关掉知识库窗口不会中断**；`.qiyide/wiki/.ingest-job.json` 记录轮次与调用数，
异常退出后重开会提示从第 N 轮继续。暂停与停止是两个语义，暂停可原样续跑。
已建档且未改动的文件由 `.qiyide/wiki/.insights.json` 跳过——文件结论本身带缓存，重跑不再重复付费。

入口：知识库 →「AI 整理」→「整个仓库建档…」。

知识条目的正文与元数据都是纯文本，可以用任意编辑器改，保存后重新扫描即可生效。模型的输出永远落在 `status: draft`，并用 `generated:` 记录是哪次模型写的——人可以改，AI 不能替你签字。

### 中文化与工程化

- 界面与文案完整简体中文；
- 独立 Bundle ID / App Group / URL Scheme / 应用支持目录，可与原版 CodeEdit 并存；
- `scripts/build.sh`（可指定目标架构）与 `scripts/package-dmg.sh`（ad-hoc 签名 + dmg + SHA256）；
- GitHub Actions 云打包：四仓库同级检出自建包、Release 构建、产出 universal dmg，推 `v*` 标签时发布到 GHCR。

## 构建与打包

**本地**

```bash
./scripts/build.sh Release        # → build/Build/Products/Release/Qiyide.app
./scripts/package-dmg.sh Release  # → build/Qiyide-<版本>-<build>.dmg
```

**本地开发版（与正式版并存）**

```bash
./scripts/package-dev.sh --no-build --run   # 3 秒重打包 + 立刻启动（改完代码已构建过）
./scripts/package-dev.sh --run              # 增量构建 Debug 再打包启动
./scripts/package-dev.sh --dmg              # 顺带产出 dmg
```

产物为 `build/QiyideDev.app`：显示名 `QiyideDev`、Bundle ID `app.qiyide.QiyideDev`，与正式版 Qiyide 的偏好、Dock 图标互不覆盖，可以同时装在同机器的 `/Applications` 里。由于 Bundle ID 不同，两套配置不共享。

**云端**：Actions → `Build DMG` → Run workflow；或推送 `v*` 标签自动构建，发布时会同时产出三处：

| 位置 | 用途 |
| --- | --- |
| **Releases** 页 | 直接下载 dmg（`Qiyide-<版本>-<build>.dmg`），推荐 |
| **Packages**（GHCR） | `ghcr.io/shadowhunt-yi/qiyide:<tag>`，用 `oras pull` 获取 |
| run 的 **Artifacts** | 临时构建产物，保留 14 天 |

> 产物为 ad-hoc 签名，首次打开需右键 → 打开，或 `xattr -dr com.apple.quarantine /Applications/Qiyide.app`。
