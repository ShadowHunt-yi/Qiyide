# 2026-10-30 · 领域建模的可读性与性能优化

承接 10-29 的三阶段落地（识别 → 投影 → 生成）与静态验证，这一轮只做两件事：
**可读易读** 与 **性能**。

## 性能：识别 9.6s → 2.8s（同仓库、同数据、结果逐项一致）

`saas-plus-ai-platform`：96 候选包 / 1892 个类 / 8 个域。

| 改动 | 原因 | 收益 |
|---|---|---|
| 作者统计合并为**一次** `git log --name-only` | 原实现每个候选跑一次 `git log -- <dir>`，96 个候选 = 96 个进程 | 耗时大头，占掉一半以上 |
| import 扫描 + 中文词提取合并为**一次**文件遍历 | 原来同一批 1900 个文件读两遍，两趟都要跑编码回退 | IO 与解码减半 |
| 中文词改用 Unicode 标量扫描，弃用 NSRegularExpression | 每文件一次 16KB 正则匹配 + 每次匹配建 NSRange | CPU 明显下降 |
| `concurrentPerform` 按文件并发 + 锁汇总 | 纯 CPU 的解析可并行 | 用满多核 |
| 组树预分组 + Set 去重 | 原「每个域扫全部叶子 + `nodes.contains` 查重」= O(域×叶子×节点) | 降到 O(叶子) |

**做法要点**：`SignalCollector`（类 + NSLock）封装累加器，避免在并发闭包里改捕获变量。
文件→候选 的映射 `fileToCandidate` 一次建好，作者统计直接反查，不再靠目录前缀匹配。

## 可读性：导图从「能看」到「能读」

1. **缩放 / 平移 / 适应窗口**。模块必然比窗口宽，靠拖窗口去凑不可行。
   - 布局缓存（`MindMapLayoutMemo`）按 `(尺寸, token, expanded, showAll)` 命中，捏合缩放不再重算布局；
   - 适配策略：换图时只缩不放（小树放大 130% 后一展开又缩回去，画面一直跳）；
     展开/折叠时只在「装不下」时缩小，保住用户手动调过的比例。
2. **两侧高度再平衡**。模块只挂在被识别为域的节点下，实测三个有模块的域全落在同一侧：
   一侧 1432pt、另一侧 232pt。加了「失衡 > 1.6 倍才把最合适的块挪过去」，
   内容 758×1451 → 928×883，且正常展开不换边（避免整棵树跳）。
3. **单域模块封顶 10**，其余折叠成虚线汇总卡「还有 N 个模块」，点一下全展开。
4. **选中高亮祖先链**：无关分支压到 0.34 透明度、连线同步淡出，回答「我在哪一层」。
5. **卡片排版**：去掉左侧色条（看着像独立竖条）、加类型图标（模块不加，否则全是噪声）、
   元信息只留「N 类 · M 模块」。
   **负责人从卡片上撤掉**——168pt 宽里「647 类 · ext.xiaoshengyu5」必然截断成「ext.x…yu5」，
   比不显示更糟；负责人仍在悬停提示、右侧详情、团队归属图里。
6. **详情面板**：面包屑（当前节点在树中的路径）+ 判定依据的权重条（依据之间本来不可比）。

## 踩到的坑（重要）

### `Button` 在 ImageRenderer 里渲染成「禁止」占位符
离屏渲染导图做自检时，右下角缩放控件（`Button` + `.buttonStyle(.borderless)`）全部变成
黄底红圈斜杠占位符，而纯 `Image` / `Text` 正常。
→ 改成自绘的 `MapChipButton`（`onTapGesture` + `onHover`）。
顺带解决焦点环、和自绘导图视觉统一。**以后这个界面的交互控件一律自绘。**

### 离屏渲染是验证「可读性」的唯一可靠手段
GUI 链路在无头启动下点不了（10-29 已确认），但「画出来长什么样」可以直接渲染：
`QIYIDE_VERIFY_SNAPSHOT=/tmp/x.png` 会渲染两张（默认 / 全展开）PNG。
字体太小、卡片挤、连线穿卡、控件坏掉——看图一眼就知道，比读代码可靠得多。

### 布局自检要有硬指标
`DomainVerification` 里加了：卡片两两相交数必须为 0、内容包围盒尺寸、汇总卡清单。
「不重叠」是排版正确性的下限，靠肉眼看图容易漏。
