## 结构地图 M1：真实模块 + 面包屑下钻

起因：用户看了「分支结构变更图」原型后指出「领域下模块是空白的，实际应该都是准确的模块，
希望类似面包屑的层级渐进」。方案见 Artifact「结构地图开发方案」，本次落地其中的 M1。

### 空白的真正原因（在基准仓库上实测）

改动前在 `saas-plus-ai-platform`（`feature/corpus-standard`，1800 类 / 7 个域）上跑识别：

| 域 | 类数 | 改动前的模块 |
|---|---|---|
| AI搭子（兜底） | 766 | **0 个** |
| Service 核心（兜底） | 266 | **0 个** |
| AI画像（portrait）（兜底） | 120 | **0 个** |
| AI语料（兜底） | 75 | **0 个** |
| Controller 核心（兜底） | 41 | **0 个** |
| AI画像 | 303 | 有，但域根 55 个类不属于任何模块 |
| AI客服 | 113 | 有，但 `biz` 记成 8（实际 18） |

三个缺口都在 `DomainAnalyzer.buildGraph / groupModules`：
1. 模块只挂给评分达标的域，兜底域创建时没有挂；
2. 同一个三级包只取遇到的第一个叶子，更深的子包被 `seen` 跳过；
3. 只处理 `parts.count >= 3` 的叶子，域根目录直属的类没有模块。

### 改法

- `DomainAnalyzer+Modules.swift`：模块 = 域的包路径下的第一级子包，含全部更深子包；
  域根直属的类归「（域根）」模块（`module:<域路径>/_root`）；兜底域同样挂模块。
- `StructureIndex.swift`：领域模型（决定）+ 一次目录扫描（事实）合成「域 › 模块 › 文件」。
  文件一律以当下扫描为准，模型只决定归属——模型旧了，新包也会按路径规则自动落位。
  归属规则「路径越长越具体」：模块节点 > 域 > 未划分；域根模块只认领恰好相等的路径。
- `Views/Structure/`：面包屑 + 四级视图（全仓 / 域 / 模块 / 子包），每一级同一种画法。
  模块下面继续沿包路径下钻，点文件在编辑器里打开。知识库窗口中间栏新增「结构」页签。
- `DomainModelStore.makeDrift` 改成按路径前缀判断覆盖，否则旧锁定模型会把新增的模块节点全报成漂移。

和方案的两处出入：
- 模块标识没有改成「仓库相对路径」。同名业务包跨 Maven 模块（app / client）时合并为一个模块，
  文件各自保留并标出处。这样不用迁移已有的锁定文件。
- 第一版原型的「域 × 层」矩阵没有保留。基准仓库多数域按功能分包，层当不了行。

## 结构地图 M2–M4：依赖事实、分支增量、确认与写回（11-06）

### 做了什么

- **依赖事实**（`StructureFacts.swift`）：文件级的「谁 import 了谁」，带行号和原文。
  Java import 按全限定名对到文件，不再按包名末段反查。内部类、静态导入、
  通配导入（包 / 类的静态成员）都落到正确的文件。显示时按文件所属的模块、域往上聚合。
- **分支增量**（`StructureDiffBuilder*.swift`）：基准取 merge-base，头部默认含工作区。
  头部全仓扫一遍 import；基准一侧只用 `git cat-file --batch` 读改过的文件重算，不切分支。
  产出四类结构变化和对应的待确认，每条带稳定标识、地图上的锚点、证据行。
- **界面**：对比条（地图 / 分支增量、目标分支、含未提交、声明范围）、一句结论、
  待确认清单（随面包屑收窄）、模块与文件上的 `+ ~ −` 标记、面包屑上的待确认数。
- **决定**（`StructureDecisionStore.swift`）：接受 / 标为违规 / 撤销，按分支落盘到
  `.qiyide/wiki/structure/decisions.json`；违规项汇成「给 AI 的修改要求」可复制。
  「新包待归属」可以一键归入往来最多的域（改的是领域模型，`MindGraph.adopt`）。

### 待确认的生成规则（偏保守，拿不出证据的不生成）

| 类别 | 何时生成 |
|---|---|
| 地图·新包 | 新模块落在兜底域或「未划分」。业务域下面新加子包不问——归属由路径决定 |
| 地图·移动 | 文件跨域移动，按「来源模块 → 目标模块」合并 |
| 依赖 | 跨域的模块对新增或消失，按「域 → 域」合并成一条；域内的只在域视图里列出 |
| 接口 | 被别的域引用的类，公开签名变了；或文件删了但还有 import 指向它 |
| 范围 | 声明了只动哪几个域时，范围外的改动合成一条 |

等着归属的新包，它自己带来的依赖不再单独问（否则同一件事要答两遍）。

### 顺手修的三个既有问题

1. **领域识别不稳定**：`makeLeaves` 按字典顺序遍历目录，词频统计又「每个候选只看前 100 个文件」，
   顺序一变抽到的文件就变。实测 `agent/suggest` 的分数在 0.659–0.70 之间跳，
   同一份代码有时 7 个域、有时 8 个。改成按目录名排序后三次运行分数一致（0.685）。
2. **仓库路径带符号链接时相对路径算错**：`/var`、`/tmp` 下的仓库，
   `module.root.path.replacingOccurrences(of: root.path, …)` 一个字都替换不掉
   （遍历给的是 `/private/var/…`），「仓库相对路径」变成绝对路径，git 路径全部对不上。
   是单元测试用临时目录建仓库时撞出来的。两边都先 `resolvingSymlinksInPath`。
3. **导图工具条在窄宽度下被挤坏**：页签从三个变四个后，「已锁定」被挤成竖排。
   页签收窄、视角菜单改成可压缩、操作区 `fixedSize`。

### 没验证的 / 已知的边界

- **完整 App 仍然没有编译过**（这台机器没有 Xcode）。`Features/Wiki` 全部文件、
  单元测试都用 swiftc / SwiftPM 编过并跑过；`CodeEditApp.swift` 里的一行钩子没编过。
- **没有推送**：提交都在本地 main（领先 origin/main 10 个提交）。两个原因叠在一起：
  助手的自动模式不允许向远端发布；并且这台机器上没有 github.com 的凭据
  （`git push --dry-run` 报 `could not read Username for 'https://github.com'`）。
  需要人来 `git push origin main`。只推提交、不推 `v*` 标签就不会触发云端构建。
- 单元测试里有 14 项会在临时目录里跑 `/usr/bin/git`。在 swiftc / SwiftPM 下都过了；
  Xcode 里测试是挂在 App 进程里跑的，App 开了沙箱，这几项在那边能不能跑没验证过。
- 点击交互只验证了「能编译 + 静态截图 + 数据路径的单测」，没有人工在真实窗口里点过。
  `run.sh open <仓库>` 可以打开真实窗口。
- 只支持 Java（沿用领域识别的范围）。接口识别是按行的启发式，跨多行的参数表只看第一行。
- 通配导入（`import a.b.*`）只落到包里的一个代表文件上，够定位模块，不够精确到类。
- 「含未提交」关掉时，依赖事实仍然读工作区的文件内容（只有改动清单按提交算）。
- 层标签（方案 M2 的后半）没有做：三处硬编码的层判定表还没统一。
- 分支增量的计算没有缓存，每次切换目标分支或刷新都重算（约 1–1.5 秒，主要是起 git 进程）。
  应用重新激活时会自动重扫一遍（人切回来看 AI 改完的结果时不用手点刷新）。
