## 知识图谱渲染卡顿优化（Qiyide Wiki）

用户反馈「图谱页面很卡」。定位到四个数量级上的浪费，全部改掉：

### 1. 按 id 取节点是 O(n) 线性查找（最致命）
`WikiGraph.node(_:)` / `neighbors(of:)` 用 `nodes.first { $0.id == id }`。
绘制时每条边调两次，232 节点 + 800 边 = 每帧三十多万次字符串比较；
左侧列表每行再调一次 `node(id).degree`，整体退化成 O(n²)。

改：`WikiGraph` 构造时预建 `nodesByID` / `indexByID` / `neighborsByID` /
`edgeIndexesByNode` 四张索引，热路径全部 O(1)，新增 `degree(of:)`。

### 2. 上千次独立描边
旧实现每条边一次 `context.stroke`、每个节点一次 `context.fill`（800 + 232 次）。
改：边按「高亮/普通 × 实线/虚线」分 4 桶，节点按「类型 × 明暗」分 12 桶，
一次性合并成 Path 再描边/填充 —— 最多 16 次绘制调用。

### 3. 无视口剔除
先算一遍屏幕坐标，`onScreen` 标记；边两端都在视口外就跳过（外扩 80pt，容下半径与标签）。

### 4. hover 每移动一像素就写 @State
`onContinuousHover` 里命中结果不变也赋值，触发整图重绘。
改：命中变化才写 `hovered`；`hitTest` 改用平方距离比较，省开方。

### 5. 其他
- 标签预算上限 150，超出按节点度数降序取（先保信息量大的），选中/悬停加粗。
- `Canvas(rendersAsynchronously: true)`。
- `WikiStore` 加 `entriesByID`，`entry(id:)` O(1)（批量操作 `selectedEntries` 是 O(k·n)）。
- `WikiStore.search` 预建小写副本 `searchRows`，避免每敲一个字对全库 `lowercased()`。
- 力导向布局（232 节点 Debug 下约 100–200ms）改为：先用力导向的螺旋初值上屏，
  后台 `Task.detached` 算收敛结果，`layoutGeneration` 代数号丢弃过期结果。
  新增 `WikiLayout.initialPosition(index:count:id:)` 与 compute 共用同一公式。
