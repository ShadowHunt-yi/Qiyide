
## Git blame 行级标注（08:25-09:40）

### 需求与设计
- 行尾显示「hash 作者 日期 摘要」，点击（单击/双击）打开该行完整变更历史 + 提交详情；覆盖新增/修改/删除（diff 展示）；随内容/分支实时更新；处理未提交/合并/重命名；全局开关。

### 实现
1. `GitClient+Blame.swift`：`blame --line-porcelain -w -M -C` 解析（含短头元数据沿用、boundary、Not Committed Yet→"未提交的修改"）；`log -L n,n:file` 行历史（COMMIT\x1f 分隔头 + diff）；`show --stat` 提交详情。**解析器用真实 crm-docs README 独立测试通过（214 行一一对应、边界标记正确）**。
2. `GitBlameAnnotation`（TextAttachment 自绘，CoreText 绘制 + 宽度测量）→ 行尾锚点覆盖换行符 NSRange(loc,1)，类型器把该区间交给附件绘制，行断行不受影响。
3. **内核小改**（CodeEditTextView）：`TextAttachment.attachmentSingleClick()` 默认空实现 + TextView+Mouse 单击时调用——折叠占位符不受影响。
4. `GitBlameCoordinator`（TextViewCoordinator）：编辑防抖 0.6s、分支/提交（manager.objectWillChange）、设置开关三路触发；文本+分支指纹去重；失败发通知；非 git 仓库静默。
5. `GitBlameHistoryView`：行历史列表（hash/作者/日期/摘要）+ 选中显示该次 diff + "完整提交"按钮（show --stat）；未提交行显示提示。
6. 开关：设置→源代码管理→"显示 Git 行级标注" + Navigate 菜单 Toggle（⌥⌘B）/"查看行历史"（⌥⌘L）；通知 `.gitBlameSettingsDidChange` 广播。
7. 协调器由 CodeFileDocument 强持有（TextViewController 对协调器是弱引用，否则被释放）。

### 已知边界
- 未保存的缓冲内容与磁盘不一致时行号可能轻微错位（git blame 读磁盘），autosave 默认开启所以窗口极小；保存后自动校正。
- `git log -L` 不跨重命名（git 本身限制）；blame 的 filename 字段在标注里保留了来源文件名信息（解析已含），重命名本身 blame 自动跟随。

## 崩溃修复：括号配对高亮越界（09:45-10:10）

### 崩溃定位（用户提供的崩溃报告）
- EXC_BREAKPOINT 由 `-[NSString enumerateSubstringsInRange:options:usingBlock:]` 抛 NSRangeException 引起，
  帧 3 = `TextViewController.findClosingPair`（CodeEditSourceEditor 本地包，括号配对高亮）。
- 触发链：SwiftUI 布局（sizeThatFits）→ updateNSViewController → reloadUI → Appearance.didSetOnController
  → emphasizeSelectionPairs → emphasizeBackwards → findClosingPair。

### 根因
`findClosingPair` 直接用 `NSRange(location: limit, length: from - limit)`（反向）/ `(from, limit-from)`（正向）调 enumerateSubstrings：
1. visibleTextRange 为 nil（布局完成前）或与光标相距 >4096 时，limit 与 from 倒置 → **负长度 NSRange**（桥接成巨大 UInt）→ 必崩；
2. 选区 stale（文本缩短后 location 超出文档）→ 越界 range。
用 ObjC @try/@catch 复现与崩溃报告同款 NSRangeException（/tmp/rangecrash.m）。

### 修复（TextViewController+EmphasizeBracket.swift）
- findClosingPair：from/limit 夹紧到 [0,length]，倒置窗口视为空返回 nil（保持方向语义）；
- emphasizeForwards/Backwards：搜索窗口锚定 from 起至少 4096 字符（visibleTextRange nil/远离时窗口不再倒置）；
- emphasizeSelectionPairs：选区夹紧（substring(with:) 越界同样抛异常，第二处隐患）。
- 新增回归测试 test_findClosingPairOutOfRangeDoesNotCrash（6 种越界形状）。

### 顺带修复（测试基建，此前整个测试文件编译不过、从未跑过）
- Minimap 测试：minimapView 是可选值未解包；且实际设计是「销毁/重建」不是 isHidden 切换；配置需 reloadUI() 生效；
  重建后 frame/insets 靠 frameDidChange 观察者异步自愈，测试里显式 layoutSubtreeIfNeeded+updateTextInsets。
- Preview 类型名 `X_Previews2/3` 违反 SwiftLint type_name（swift test 的 PrebuildCommand 直接判失败）→ 重命名为 `XPreviews2/3`。
- 测试运行命令：`swift test --disable-sandbox`（manifest 编译也有嵌套沙箱问题，--disable-sandbox 关 SwiftPM 子进程沙箱）。
- 结果：TextViewControllerTests 20/20；全包 65/65 全绿。

## 启动报「无法获取 blame」+ 文件树 No Filter Results 重叠（10:21-11:00）

### blame 报错根因（实测证据）
- 工作区 `~/project` 是 **git init 但零提交** 的仓库：`git log` → `fatal: your current branch 'main' does not have any commits yet`；
  `isGitRepository` 仍为 true（validate 只看 --is-inside-work-tree）→ blame 必失败。
- 三类真实报错（已实测）：空仓库 `fatal: no such ref: HEAD`；未跟踪 `fatal: no such path 'x' in HEAD`；
  仓库外 `fatal: 'x' is outside repository at '...'`。旧代码把三者都当故障弹横幅。
- 旧代码还用「工作区主仓库」的 cwd 执行 blame，嵌套仓库（`~/project/saas-plus-crm` 等自身是仓库）里的文件必然
  `no such path`。

### 修复
- `GitClient.run(_:in:)`：支持指定 cwd。
- `GitClient+Blame`：新增 `GitBlameUnavailable`（notARepository/noCommits/untracked）；
  `repositoryRoot(containingFile:)` 用 `rev-parse --show-toplevel` 从文件目录解析所属仓库（支持嵌套仓库）；
  blame/log -L 都在该仓库执行；fatal 输出按消息归类为「预期不可用」，未识别才视为真实故障。
  `lineHistory` 遇不可用返回空数组（面板显示空态）。
- `GitBlameCoordinator`：去掉 `manager.isGitRepository` 门槛（空仓库/工作区根非仓库都会误判）；
  `catch is GitBlameUnavailable` 静默卸载；真实故障每文件只提示一次（hasNotifiedFailure），描述带文件名。

### 文件树「No Filter Results」重叠根因 + 修复
- 根因1：`handleFilterChange` 只在 `filteredContentChildren[root]` 存在且为空时显示，清除过滤后缓存被清空（取不到），
  隐藏分支永不执行 → 标签残留压住文件行。修复：`updateNoResultsState()` 用 isFiltering 显式推导，始终双向更新。
- 根因2：标签挂在 `outlineView`（文档视图，高度=整棵树内容高度）上居中 → 压在某行上且随内容滚动。
  修复：改挂 `scrollView` 居中（可视区），文案走本地化「没有匹配结果」。
- 根行隐藏状态成对管理（isRootRowHidden + unhideRows），避免清空过滤后整棵树不可见。
- `ProjectNavigatorNSOutlineView.reloadData()` override 统一同步提示状态，覆盖所有重载路径；
  菜单 reloadData 改为「先清过滤缓存再 reload」（原顺序会让树显示旧结果）。
- 紧凑目录链在「最近文件」过滤下不再合并（与搜索一致）。
