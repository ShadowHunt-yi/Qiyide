## 教训：`-onlyUsePackageVersionsFromResolvedFile` 会把本地包锁回远程

- 现象：pbxproj 已改为 `XCLocalSwiftPackageReference`，构建仍 `Fetching from .../CodeEditTextView|SourceEditor|Languages`。
- 根因：`Package.resolved` 里仍有 codeeditsourceeditor/textview/languages 三条 remote pin；加上 `-onlyUsePackageVersionsFromResolvedFile` 后，Xcode 按 pin 用远程 SourceEditor 0.15.1，而其清单仍是远程依赖 TextView/Languages → 三者一起被 fetch。
- 修复：从 `Package.resolved` 移除这三条 pin（34→31，保留 codeeditkit/symbols），删除两处 SPM 缓存里的 `CodeEditSourceEditor-*`、`CodeEditTextView-*` 裸仓库；**重跑时不要再带该 flag**。
- 规则：本地路径依赖接入后，resolved 里对应 pin 必须删除，否则任何"按 resolved 解析"的路径都会回退远程。

## 构建：SwiftLint 插件会 lint 第三方依赖并报 error

- 现象：`xcodebuild` 输出大量 `Spaces over Tabs` / `Line Length`，其中 `LanguageServerProtocol/Tests/...:16 error: line_length`（278>200）会中断构建。
- 原因：依赖包自己的 `Package.swift` 声明了 `SwiftLint` 插件，构建它们时必然执行；`-skipPackagePluginValidation` 只跳过信任校验，不阻止运行。
- 官方开关（读 `SwiftLintPlugin/Plugins/SwiftLint/main.swift:31-34`）：环境变量 `DISABLE_SWIFTLINT` 非空即完全跳过 lint。
- 落地：新增 `scripts/build.sh`，内置 `DISABLE_SWIFTLINT=1` + `-skipPackagePluginValidation -skipMacroValidation` + `-destination 'platform=macOS,arch=arm64'`。
- 坑：脚本里 `$CONFIG` 后直接跟全角括号会被 bash 并进变量名，必须写 `${CONFIG}`。

## 运行时崩溃修复（15:57）

- 崩溃：`SIGTRAP` in `TextViewController.textViewInsets.getter` ← `updateTextInsets()` ← `gutterViewWidthDidUpdate()` ← `GutterView.init`。
- 根因：上一轮「迷你地图按需创建」把 `updateTextInsets` 的守卫从 `textView != nil, minimapView != nil` 改为只判断 `textView != nil`。

  守卫放宽后，回调走到 `textViewInsets`，此时 `gutterView` 尚未赋值（IUO）→ 强解包崩溃。
- 修复：`textViewInsets` 改用 `gutterView?.frame.width ?? 0`；`updateTextInsets` 增加 `gutterView != nil` 守卫。
- 顺带：崩溃报告里线程 3/4 同时阻塞在 `git fetch`，原因是周期刷新 `.task(id:)` 挂在会被重建的分页视图上，
  每次重建重启一条 fetch，而 `git fetch` 阻塞读管道不响应取消。已把轮询移到 `SourceControlNavigatorView` 的容器 `VStack`，
  `.task(id: fetchRefreshServerStatus)`，每轮重新读取 `workspace.sourceControlManager`。

- 追加证据：系统浅色外观；`Assets.car` 中 AppIcon 的 AssetType = Icon Image、Icon Index 正常；
  `NSWorkspace.icon(forFile:)` 在 32/64/128 三档渲染均为新图标（含 Tahoe 玻璃底座）；
  LaunchServices 数据库只有一条记录（无重复副本）；`lsregister -f` 无效。
- 差异点：`Signature=adhoc`、`TeamIdentifier=not set`，本机无可用代码签名身份（0 valid identities），
  且应用不在 /Applications 下。
- 处置：① `killall Dock` 重启台前调度所在进程；② AppDelegate 启动时显式 `NSApp.applicationIconImage = NSImage(contentsOf: AppIcon.icns)` 兜底。
- 待验证：Dock 重启是否生效；若仍不行，需要用正常签名（Xcode 登录开发者账号）运行来验证是否与 ad-hoc 签名有关。

## NSWindowCollectionBehavior 核查（16:59）

- 全工程仅一处设置：`FeedbackWindowController.showWindow` 中 `[.transient, .ignoresCycle]`（辅助窗口标准写法，副作用是不进台前调度/⌘` 循环）。
- 主工作区窗口（`WorkspaceDocument.makeWindowControllers`）与 SwiftUI `Window` 场景（welcome/about/settings/extension）均未设置 → 默认 `.managed`，正确。
- 结论：该属性只决定窗口是否被台前调度/调度中心收录，不参与图标绘制；台前调度图标异常与它无关，改它无效。
- 附：产物 `CFBundleIdentifier = app.qiyide.Qiyide`，无 `LSUIElement`/`LSBackgroundOnly`，`NSPrincipalClass` 未设置（默认 NSApplication，可接受）。
